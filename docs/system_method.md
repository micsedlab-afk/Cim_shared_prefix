# System-path decoder latency (L1)

Owner: `work/system-path`; base `582dfec94154b6ff795eeff4616d5bcec7809e8c`.

## Causal accounting

`evaluate_decoder()` processes one block profile per output token and charges every decoder layer. The serial dependency chain is GPU QKV projection → query quantization/transfer → physical signed prefix QK → local signed partial combination → completed-score transfer or GPU partial combination → full-context softmax, attention/value, output projection, normalization, MLP and structural operators. An independently modeled suffix QK term is included. All GPU stages except the original **full** attention-score stage remain charged from the supplied LLMCompass record. Charging the full LLMCompass score and accelerator prefix score together would double count prefix QK.

For a model with `L` layers, batch `B`, query heads `Hq`, KV heads `Hkv`, prefix `K`, head dimension `d` and signed split factors `s` (storage) and `a` (array evaluations), physical key bytes per nonpadding tile `(layer, token range)` are `ceil(tile_tokens * Hkv * d * key_bits / 8) * s`. Score traffic per output token is `L * B * Hq * K * bits_per_partial / 8 * transmitted_partials` bytes. Reduction count is `L*B*Hq*K*(a-1)` pairwise partial combines, split between local and GPU according to transmitted partial count; neither path is silently free.

A finite SRAM capacity is consumed by pinned whole tiles plus at most one streaming scratch tile. If the prefix fits, it is transferred/programmed once, before the first decode step. Otherwise the largest tile is reserved as scratch; pinned tiles are selected in descending byte size. Unpinned tiles are **transferred and reprogrammed on every generated step**, including the first; the first-token one-time placement contains pinned tiles only. Residency is therefore shared by batch requests without replicating prefix K. One scratch slot is a conservative fixed-location execution policy, not an LRU-cache performance claim. Tile alignment/periphery capacities must be separately imposed when known.

Per-token serial latency is the sum of `initial pinned transfer`, `initial programming`, `streaming refill`, `streaming programming`, `physical QK (native scalar MAC-equivalent evaluations, not complete macro cycles)`, `GPU-to-CIM query conversion and transfer`, `local signed reduction`, `CIM-to-GPU score transfer`, `GPU partial merge`, `GPU suffix QK`, `all non-score LLMCompass GPU stages` and `structural GPU work`. The first-token latency includes the cold placement. Reported `mean_tpot_s` is the finite-output average (including placement amortization); `total_decode_s` sums the actual output steps. For steady-state latency inspect later `TokenLatency` entries.

## Overlap evidence

Default: **serial**, with no hidden concurrency. An optional first-streamed-tile prefetch may overlap the corresponding layer's GPU QKV projection, bounded by `min(prefetch transfer + programming, QKV stage duration)`. Other tiles, local reduction, score transfer and softmax are not overlapped. A dedicated DMA path, independent programmer, known prefix before query and a provenance record are prerequisites. `evidence_kind=sensitivity` is explicitly hypothetical. `evidence_kind=physical_trace` additionally requires a schedule receipt, but the receipt must still be audited independently before publication. No evidence in this branch demonstrates physical overlap.

## Upstream interface and precision restrictions

Run `bash scripts/acquire_upstreams.sh` on a credentialed workstation. The upstream code is not vendored. `magma_a100_block()` consumes genuine `magma.llmcompass-native-a100-point/v1` JSON produced by `MAGMA-gpt/src/magma/llmcompass_native_a100.py`, which calls the vendored `TransformerBlockAutoRegressionTP(...).compile_and_simulate(..., "heuristic-GPU")`. That implementation uses exactly 16 query and KV heads, `d_head=128`, `d_model=2048`, `FFN=8192`, FP16, HBM2e, one A100. Its available context grid is `{128,512,2048,8192,16384}`; batch grid `{1,2,4,8,16,32,64}`. Each decoder step requires a profile at **exact** context `prefix+suffix+step+1`; no score interpolation or silent geometry conversion is allowed. A single frozen-context model point does not establish an output-length sweep.

The source MAGMA record models a full-context attention score. When the accelerator computes prefix QK, require separately grounded `suffix_score_s` for the suffix and already-decoded nonprefix tokens; this is zero only when suffix and prior generated tokens are both empty. Full softmax and attention-apply timings remain at the matching full context. MAGMA itself marks KV cache structural updates, reshape, transpose and concat as uncharged. `structural_s_per_token` therefore requires an explicit source for these operations (and sampling/end-of-block logic as appropriate); an assumed zero must be labeled as an unqualified approximation. There is no direct physically matched HBM4 denominator from MAGMA's native A100/HBM2e model.

`PathCalibration.provenance` requires sources for physical array rate, each independent link, signed programming, local/GPU reduction and query quantization. A rate labeled merely `HBM4PiM` is insufficient: supply the exact workload, device, precision, physical endpoint, measurement/model identifier, and which bus it characterizes. HBM4PiM GPU operator calibration may supplement MAGMA where it is compatible; it is not silently substituted for the vendor model. Q4 prefix keys and signed factors are inherited from `SignedMapping`, while remaining GPU operator precision is governed by the profile. Other LLMs/GQA geometries require independently generated compatible LLMCompass profiles and cannot use the fixed MHA A100 native adapter.

The original `shared_prefix_cim` branch pin in `scripts/acquire_upstreams.sh` and `SRAM2LLM` supply arithmetic/transfer semantics; **this timing module does not alter or claim to have run their hardware models**. Signed factors default to `key_storage_factor=2` and `array_evaluations_per_logical_operation=4`, and must be checked against the exact source-native Q/K sign implementation before attaching physical measurements.

## Reproduction

From the root: `python -m unittest discover -s tests -v` and, given exact upstream timing/calibration files, `python scripts/run_system_path.py --manifest scenario.json --output results/system_breakdown.json`. The manifest schema is `cim-shared-prefix-system-scenario/v1`, with `workload` (Workload fields), `sram_bytes`, `tile_tokens`, `calibration` (PathCalibration fields, with all provenance), `gpu_profile_files` (one file and suffix/structural timing sources per output), and optional `signed_mapping`, `scores` and `overlap`.

`results/system_path_fixture_scenarios.{csv,json}` provide **synthetic fixture executions solely for checking accounting and sensitivities**; they contain neither measured CIM timing nor native LLMCompass outputs. The fixture computes physical byte/work counts from representative GQA/MHA geometries and propagates hypothetical named rate inputs, permitting the latency decomposition and refill invariants to be inspected without fabricating hardware measurements.
